The [current catalog](https://developers.openai.com/api/docs/models) and [pricing](https://developers.openai.com/api/docs/pricing) confirm Luna and Terra. Both support [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). The text adapters use strict schemas, Standard service, no reasoning and no paid tools. Speech uses minimal reasoning within its output-token cap. This coding session's Astra/Fast settings do not select the game's model or tier.

The [deprecation register](https://developers.openai.com/api/docs/deprecations) marks tts-1, tts-1-hd and gpt-4o-mini-tts for January 6, 2027 retirement, with Realtime mini as successor. The temporary Speech API adapter has been replaced. No retirement is listed for the selected Realtime mini model as of this verification. Paid audio remains off by default. GPT-5.4 nano is also deprecated, scheduled for April 1, 2027 removal. No retirement was listed for selected Luna/Terra models when checked; recheck before live use.

The [Speech guide](https://developers.openai.com/api/docs/guides/text-to-speech) explicitly says the replacement is **not** supported on /v1/audio/speech. No durable exact-transcript Speech endpoint was established by current official documentation. This implementation uses the [Realtime WebSocket protocol](https://developers.openai.com/api/docs/guides/voice-websockets?api=realtime): wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1-mini (Workers uses HTTPS Upgrade). [Client events](https://developers.openai.com/api/reference/resources/realtime/client-events) establish session.update, disabled VAD/transcription, minimal reasoning, empty tools, output audio/pcmu, marin, response.create with conversation:none and max_output_tokens. [Server events](https://developers.openai.com/api/reference/resources/realtime/server-events) establish audio deltas, transcripts and completed response usage. The [cost guide](https://developers.openai.com/api/docs/guides/voice-latency-cost?api=realtime) describes per-response input/output accounting. This is conversational Realtime, not duration-billed GPT-Live. It is not an exact-verbatim speech guarantee; both reported transcripts are checked before any playback. Live access and one short accepted/playable clip were established; this is not a general voice-quality, fidelity or provider-billing guarantee.

One project credential can route all roles subject to permissions. Separate dev/prod projects and keys isolate spending; a key per model is unnecessary. See [authentication](https://developers.openai.com/api/reference/overview#authentication), [permissions](https://developers.openai.com/api/docs/guides/rbac), and [spend limits](https://developers.openai.com/api/docs/guides/spend-limits). Alerts alone are not hard limits. Even enforced provider limits can overshoot slightly; this app reserves allowance before requests.

The engine owns maps, dice, combat, damage, turns and legal actions. Fixed three-shard facts and chapter goals cannot be replaced by model output. Generated text adds bounded flavor, not autonomous rule adjudication or a semantic truth guarantee. Recipes select existing classes/colors; no images, arbitrary SVG, HTML, code or new game assets are generated. Bots remain scripted. Intent suggestions require confirmation through ordinary controls.
